1 · How to read this

Every box is one bot turn and maps 1:1 to a Twilio Content API template. The mono code is the prototype state id; the right-hand chip is the content type plus its session class. Branch columns are the user's reply options. This is version B: identify first, collect the rest during travel. The earlier triage-first variant (A) has been dropped.

SESSION CLASS
IS — in-session, free-form, no approval. Valid only inside the 24-hour customer service window.
OOS — out-of-session; requires a pre-approved template. Only the symptom-check alert is OOS.
COMPONENT CHOICE RULE
≤ 3 options → quick-reply (title ≤ 25). 4–10 options → list-picker (row ≤ 24, description ≤ 72, button ≤ 20). Selection sets larger than 10, or any multi-select, are not native — see section 9.

3 · Flow — ID first, then location, then antivenom

Rationale: the two irreversible facts — which snake, which facility — are established in the fewest possible turns, and the photo is asked for while the snake may still be in sight. Location is only needed to route to a facility, so it is asked once the image is already uploading and never blocks the identification. Symptoms and time of bite are collected while the victim is waiting for or in transport. Cost: no severity read before identification, and the module gets no syndromic prior.

id_prompt
Straight from welcome to identification — see section 4
The bite path's opening: no location request, no time question, no symptom list, no pre-ID triage turn.
quick-reply · IS
loc_photo
Location request, during photo analysis
Fires the moment the image lands, replacing the "Analyzing the image…" filler: the wait becomes the turn that collects location. It also tells the module where the photo was taken, which narrows candidates by local range. Asked once per session — a retaken photo, a "find antivenom" tap or a snake-catcher request never re-asks. On the no-photo branch the request moves to whichever step first needs it (loc_bite for care, loc_id for a catcher).
location · IS
DEFERRED TO THE SYMPTOM CHECK (SECTION 7)
Time of bite runs after directions are on screen, as the first turn behind the alert's "OK". The symptom list is the consolidated checklist, asked once.

4 · Identification

The opening prompt offers the two photo routes first; everything else in this section follows from which of the three options was taken.

id_prompt
Identification method · three options
"Photo ID is the best way to see if a snake is venomous. Only take a photo if you can keep a safe distance."
Take a photo · Use existing photo · No photo, snake is gone. Both photo options go straight to the upload — there is no intermediate "send a photo" turn. The distance warning lives in the body, not on a button, because the instruction that keeps someone safe must not be the thing that gets truncated at 25 characters.
quick-reply · IS
PHOTO
upload → loc_photo → species_results
Vision match is stubbed in the prototype as a distribution, not four independent scores: 86/9/3/2%, summing to ~0.99 with the remainder across the other 57 species. Only the leader clears the 80% threshold, so the LOW CONFIDENCE chip carries the three alternates. Ranked carousel; confidence sits beside each common name.
DESCRIPTION · VIA no_photo
idkey loop → confirm or species_results
Module-driven adaptive key over 61 species. It picks each node by split gain, reweights on every answer, and stops at 0.85 confidence or five questions. Design renders whatever it is handed and never authors a question.
SKIP · VIA no_photo
→ loc_bite → hospital
Any-antivenom facility list, no species named. Location is collected here because this branch never uploaded a photo. Withheld entirely on the ID-only intent.
Key presentation rules Design owns
Colour rows carry a reference swatch; habitat rows a place glyph; markings a small sketch (nothing for "plain"); hood a cobra-hood glyph. Lengths spell out metres and the redundant list button is dropped. The first list also carries "I know the species" — typing a name short-circuits the key straight to the confirmation card. Illustrated lists reserve the icon slot on every row so labels share one left edge.
confirm
Species confirmation card
Photo, common name, scientific name, venom status. Status is rendered verbatim from the module's venomStatusLabel — "Venomous." / "Venomous (rarely seen)." / "Mildly venomous." / "Non-venomous." Design does not soften or grade it: venom status is a fact about the species, not a probability. Any doubt belongs to the identification, so the hedge sits on the ID line ("Based on your photo." / "Based on your answers.") alongside match confidence and the LOW CONFIDENCE chip. Venomous species add an emphasised SEEK CARE NOW (sent as WhatsApp bold in the payload). Buttons branch on intent and venom status: venomous bite → first aid + antivenom; non-venomous bite → symptom screen (section 6); spit → hospital; ID-only → more info / snake catcher / retake photo.
card · IS

6 · Non-venomous ID with a reported bite

A non-venomous ID does not close a bite case. The identification is a probability and the confirm card says so; the syndromic screen is the safety net that catches a wrong ID. Any positive sign overrides the identification and the case becomes a hospital case. The route is binary — Design scores nothing.

nv_symptoms
Syndromic screen · multi-select
"A Southern African Python bite is not venomous, but an ID can be wrong. Which of these are happening now?" Six envenoming indicators: spreading swelling · severe or worsening pain · bleeding that will not stop · drooping eyelids or blurred vision · numbness, tingling or dizziness · trouble breathing or swallowing. Multi-select is emulated — WhatsApp lists are single-select.
list-picker · IS
ANY POSITIVE SIGN
nv_positive → hospital
"What you describe can be a sign of envenoming. The ID may be wrong — treat this as a venomous bite." Then keep-still first aid and the facility list. Saying the ID may be wrong is the point: hedging here would read as reassurance.
NONE OF THESE
nv_wound_care
Wash · dress · watch for infection · tetanus shot. Terminal but re-enterable: "Symptoms have started" runs the screen again, because envenoming can declare itself hours later.

8 · Module seams

↗ SEAM A · DESIGN → ID MODULE
Emitted when the description path opens, re-sent with each answer. Carries session, channel, entry point, victim ("self" — the bot no longer asks, since no copy branched on it), location, and syndromicPriors: primary symptom plus the time-of-bite bucket id, never a collapsed minute count. The whole object is omitted when triage never ran — which is the normal case in version B.
↙ SEAM B · ID MODULE → DESIGN
Ranked candidates with confidence, venom status and label, syndrome class, antivenom product, alertIntervalMin and cadenceBasis, firstAid class, care level, tier, notes, and firstCheckDueMin. Design renders these unchanged. Design must not implement ranking, symptom→syndrome mapping, alert cadence, or any clinical value.

9 · Channel constraints that shaped the flow

ConstraintConsequence in this spec
No multi-select listThe symptom checklist is not native. Ship it as the two sequential single-select lists in section 7, an accumulating list with a "Done" row, or a deep link into the app. The prototype shows the intended UX.
10 rows per listSymptom groups are capped at five rows each; the terminal menu is exactly four.
No date/time pickerTime of bite is a text turn anchored on the session clock, parsed to the minute server-side.
Carousel text is staticThe ranked candidate set and every confidence % must be pre-built server-side once the module returns, then baked into the card bodies.
3 quick-reply buttons, 25 charsAny turn with four or more options — plans changed, terminal menu — is a list-picker instead, one tap deeper.
24-hour session windowOnly the symptom-check alert is out of session and needs approval. Everything after it rides the reopened session.

10 · Open for review

Clinical sign-off
Immobilisation sentences, the S-7 neuro instructions, and the six key symptom nodes all follow the Eswatini 2021 guidance but are unsigned.
Vision model
Photo confidences are hardcoded. The real path needs the model's ranked output and a policy for low-confidence sets.
Facility service (Seam C)
Distance, travel time, vial counts and phone numbers are static. Needs a location query emitting real stock.
Time buckets
Bites older than six hours collapse into one bucket, and a bite before midnight cannot be entered at all.
Unresponsive victim
The flow has no path for a victim who stops answering mid-sequence.
